# Publishing this workspace to GitHub

Use one repository containing the ROS source, project scripts, tests, Windows
bridge, and technical documentation. Downloaded dependencies are restored from
the pinned root `dependencies.repos` file.

## What is included

| Path | Decision |
| --- | --- |
| `src/` | Include the modified Franka ROS 2 source, custom controllers, launch files, package metadata, licenses, and notices. |
| `scripts/` | Include the Ubuntu tools, supervisors, diagnostics, and export helper. |
| `config/` | Include the Fast DDS profile; its interface addresses describe the existing lab setup. |
| `tests/` | Include the Python tests and configuration checks. |
| `windows_vlm_bridge/` | Include bridge source, its README, requirements, and sample action JSON. |
| `docs/` | Include technical operation guides and historical Windows handoffs, with the exclusions below. |
| `README.md`, `UPSTREAM.md`, `dependencies.repos`, `.gitignore` | Include repository setup, provenance, dependency revisions, and ignore rules. |

## What stays local

| Path or content | Reason |
| --- | --- |
| `build/`, `install/`, `log/` | Generated by building on each computer. |
| `src/libfranka/`, `src/franka_description/` | Unmodified external dependencies restored from pinned commits. |
| `debug/`, `session_logs/`, rosbag recordings | Experimental traces and runtime output. |
| `handoff/`, `exports/` | Transfer archives and generated source snapshots. |
| `.venv-qwen/`, other virtual environments, Python caches | Local installations and generated files. |
| `.vscode/`, `.codex/`, `.agents/` | Local editor and agent settings. |
| `july_13_progress.md`, `docs/july_21_progress.md` | Dated local progress reports. |
| `docs/manager_project_dialogue_mandarin.md`, `docs/fr3_teacher_visit_study_guide.md`, `docs/proposal/` | Meeting, study, and presentation material outside the development handoff. |
| `.env*` except `.env.example`, `secrets/`, private key files | Machine-local credentials and environment values. |
| `datasets/`, `checkpoints/`, `models/` | Data and model artifacts maintained separately. |

The exporter uses an explicit list of source directories plus `.gitignore`
rules. New top-level source directories must also be added to the exporter.
The ignore rules do not remove existing local files.

## Why an export is needed for this checkout

The working machine has a real Git repository at `src/.git`, pointing to the
Franka upstream repository. The workspace root has an empty `.git` directory
and is not an initialized repository. The modified controllers live inside
`src/`, while most project scripts and tests live outside it.

Running `git init` and `git add .` in the original workspace would encounter
an embedded `src` repository. That can record a Git link instead of including
its working files, losing the intended self-contained source handoff.

The exporter copies the current working files into a fresh directory and omits
all `.git` metadata. It includes uncommitted source modifications and untracked
source files allowed by the ignore rules. It preserves the original checkout
and its history. The resulting snapshot starts a new repository history.

## Create the source snapshot

Run from the original Ubuntu workspace:

```bash
cd ~/franka_ros2_ws
python3 scripts/export_github_snapshot.py exports/github/franka_ros2_ws
```

The destination must not already exist. For another export, choose a new path,
such as `exports/github-v2/franka_ros2_ws`. It is a point-in-time copy; later
changes in the original workspace are not synchronized automatically.

## Initialize and inspect the exported repository

Create an empty GitHub repository in your own account. A private repository is
a suitable starting point for sharing between your computers. Leave GitHub's
README, license, and `.gitignore` initialization options unchecked.

In the exported directory:

```bash
cd ~/franka_ros2_ws/exports/github/franka_ros2_ws
git init -b main
git add .
git diff --cached --stat
git status --short
```

Confirm the custom controller files, scripts, tests, and bridge files appear.
This command should produce no output; mode `160000` would indicate an
unexpected nested repository:

```bash
git ls-files --stage | awk '$1 == "160000" {print}'
```

Review the staged files before committing. The technical guides retain the
original lab addresses and example paths. Shared-secret examples use
placeholders; actual `FR3_BRIDGE_SECRET` values belong in each machine's
environment. `.gitignore` prevents adding matching untracked files; it cannot
remove a secret already present in a source file or Git history.

## Commit and push

Replace `YOUR_GITHUB_USER` and `YOUR_REPOSITORY` with your own values:

```bash
git commit -m "Import FR3 ROS 2 development workspace"
git remote add origin https://github.com/YOUR_GITHUB_USER/YOUR_REPOSITORY.git
git push -u origin main
```

Use your usual GitHub authentication. These commands are instructions for the
exported directory; the preparation helper itself does not commit or push.

## Clone on the second computer

For reading and editing, cloning the repository is enough. ROS installation is
needed when you want to run ROS-dependent scripts or build the packages.

In Windows WSL's Ubuntu terminal:

```bash
cd ~
git clone https://github.com/YOUR_GITHUB_USER/YOUR_REPOSITORY.git franka_ros2_ws
cd franka_ros2_ws
```

Follow [DEVELOPMENT.md](DEVELOPMENT.md) to restore dependencies and build.

For ongoing development, use ordinary clones of this new repository on both
machines and exchange changes with Git commits, pushes, and pulls. Keep the
original Ubuntu checkout as a backup while validating a fresh clone; its nested
`src/.git` repository is still separate from the exported repository.
